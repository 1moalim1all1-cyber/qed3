# تجهيز الموقع للنشر — اقرأ قبل تشغيل الطلبات

## ما تم إنجازه
- الحفاظ على التصميم والصور وتأثيرات الحركة.
- إلغاء كشف أسعار الجملة في كتالوج عام؛ تحفظ في wholesalePrices وتظهر للتجار المعتمدين فقط.
- تسجيل وإنشاء حسابات باستخدام Firebase Authentication (Email/Password).
- صلاحيات Firestore: تعديل المنتجات وحالات الطلبات للمدير فقط، وطلبات المستخدم تخص صاحبها.
- عدم قبول طلبات أثناء عرض الكتالوج التجريبي أو انقطاع Firebase.
- إنشاء الطلب بحالة pending_review، بدون اعتباره فاتورة بيع مؤكدة أو خصم مخزون أو تحديد سعر نهائي.
- لوحة إدارة مؤمنة بشرط admin custom claim، وإضافة وحذف منتجات وتحديث حالات الطلبات.

## خطوات تشغيل Firebase
1. أنشئ مشروع Firebase جديد أو استخدم مشروعك الحالي.
2. فعّل Authentication > Sign-in method > Email/Password.
3. أنشئ قاعدة Firestore بوضع Production.
4. أضف Web App من Project settings وانسخ إعداداتها داخل firebase-config.js بدل YOUR_... (هذه مفاتيح عميل عامة وليست كلمة سر).
5. أضف دومين الموقع في Authentication > Settings > Authorized domains.
6. افتح terminal في مجلد المشروع: `npm install -g firebase-tools` ثم `firebase login` ثم `firebase deploy --only hosting,firestore --project YOUR_PROJECT_ID`.
7. أنشئ حساب المدير بالتسجيل العادي من الموقع. بعدها عيّن custom claim `admin:true` لهذا الحساب باستخدام Admin SDK على بيئة آمنة موثوقة، ثم سجّل الخروج/الدخول. لا تضع مفاتيح service account داخل الملفات المرفوعة.
8. من لوحة الإدارة أضف منتجات حقيقية بالأسعار والصور والمخزون المؤكد خارج هذا النظام حتى يتم تطوير إدارة المخزون.
9. لاعتماد تاجر غيّر الحقل `dealerApproved` للمستخدم المقصود إلى `true` من Firebase Console بحساب مدير موثوق. لا تسمح للمستخدمين باعتماد أنفسهم.

## حدود النسخة
- ليست منظومة دفع أو شحن إلكتروني متصلة، ولا يوجد واتساب API تلقائي أو كوبونات أو نقاط أو بوت ذكي.
- فاتورة ضريبية / PDF وExcel لم تُنفّذ بعد، والطلب هنا **طلب عرض سعر ومراجعة** وليس بيعًا تلقائيًا.
- لا تعتبر الأسعار والكمية المحسوبة على جهاز العميل مصدر ثقة. تأكيد الأسعار والمخزون والتكلفة النهائية يجب أن يتم من الخادم أو من الإدارة قبل السداد.
- إعدادات Firebase الفعلية، اختبار قواعد Firestore بواسطة Emulator، واختبار تجربة مستخدم كاملة مطلوبين قبل قبول طلبات فعلية.
- الصور والمنتجات التجريبية وأي ادعاءات تسويقية يجب مراجعتها وإبدالها ببياناتك وصور لديك حق استخدامها.
- تطبيق الهاتف الأصلي غير موجود؛ هذه نسخة موقع متجاوب مع الأجهزة.

## GitHub Pages
يمكن نشر الموقع كواجهة ثابتة، لكن Firebase Authentication يجب أن يحتوي الدومين ضمن Authorized domains، ويجب نشر قواعد Firestore بشكل مستقل بأوامر Firebase CLI. نشر ملفات HTML وحدها لا ينشر القواعد.

## تدفق المبيعات المضاف
- العميل يسجل دخول، يحدد المنتجات، ويدخل اسم المستلم والموبايل والمحافظة والعنوان ويختار الدفع عند الاستلام فقط.
- الطلب يُحفظ فعليًا في Firestore ويظهر في لوحة الإدارة مع العنوان والمنتجات والكميات.
- المدير يراجع المخزون والتسعير ويدخل الإجمالي النهائي ثم يؤكد، ويحدّث رقم بوليصة الشحن والحالة.
- **لا يوجد حجز آلي للمخزون، ولا حساب شحن آلي، ولا رسالة تأكيد واتساب تلقائية، ولا تحصيل إلكتروني.** لا ينبغي إبلاغ العميل بتأكيد شراء أو شحن إلا بعد المراجعة والتواصل اليدوي معه.
- لا تفعّل المبيعات العامة قبل اختبار عميل فعلي ومدير فعلي وقراءة/كتابة القواعد في مشروع Firebase الصحيح.
- بيانات المنتجات والسعر الظاهر قد تكون تجريبية؛ استبدلها قبل الإعلان.
