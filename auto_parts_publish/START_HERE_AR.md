# تشغيل مشروع Qed3 — اقرأ قبل النشر

**المشروع:** `qed3-2a2d8` — ملفات الموقع وقواعد Firestore مضبوطة عليه.

## أولاً: في شاشة Firestore اللي صورتها
لا تنشئ مستند `users` يدويًا. أغلق نافذة Create document؛ مجموعة `users` ستظهر تلقائيًا عند إنشاء أول حساب بالطريقة الصحيحة. لا تكتب أي كلمة مرور داخل Firestore.

## رفع الموقع وقواعد الحماية معًا
1. ثبت Node.js LTS على جهاز كمبيوتر: https://nodejs.org/
2. فك ضغط هذا الملف.
3. على Windows شغّل `deploy-windows.cmd`، أو على Mac/Linux شغّل `deploy-mac-linux.sh`.
4. سجل دخولك بحساب Google صاحب مشروع Qed3 في صفحة الدخول التي يفتحها Firebase.
5. سينشر Firebase الملفات على Hosting ويرفع `firestore.rules` و `firestore.indexes.json`.
6. افتح Firebase Console وتأكد أن المشروع المحدد `qed3-2a2d8`، وتأكد أن Firestore Rules منشورة.

## حالة المميزات — مهم
- هذا رفع **للواجهة وقواعد البيانات فقط**، وليس تأكيدًا أن المبيعات جاهزة.
- صفحة الموقع الحالية تستخدم **Email/Password في Firebase Auth**. أنت طلبت لاحقًا استخدام **رقم الموبايل وكلمة مرور بدون كود SMS**. لا يمكن تشغيل هذه الطريقة بأمان بالواجهة وحدها. تحتاج Backend موثوقًا لإنشاء حسابات وتجزئة كلمات المرور وتقييد محاولات الدخول، أو تغيير الطريقة. لم ننفذ Backend في هذه الحزمة، لذلك لا نعتبر تسجيل الموبايل جاهزًا.
- حساب الإدارة الحالي يحتاج Firebase Auth user مع **admin custom claim** يتم تعيينه من بيئة موثوقة. **لا تكتب admin:true في مستند Firestore بغرض منح صلاحيات الإدارة**؛ لن يعمل.
- الكتالوج يبدأ فارغًا إذا لم تضف منتجات حقيقية. لا توجد مشتريات تلقائية أو تحصيل دفع أو تكامل شحن أو واتساب API.
- الطلب الحالي قيد المراجعة، الدفع عند الاستلام فقط، ولا يعد فاتورة بيع معتمدة قبل موافقة الإدارة.

## ماذا بعد الرفع؟
ننشيء ونختبر نظام دخول الهاتف/كلمة المرور بخادم آمن، نجهز حساب المدير، نضيف المنتجات الحقيقية، ثم نجرب: تسجيل مستخدم، إرسال طلب، ظهوره للإدارة، تحديث حالته، ومحاولة وصول غير مصرح بها.

لا تشارك كلمة مرور Google ولا مفاتيح Admin SDK أو Service Account.
